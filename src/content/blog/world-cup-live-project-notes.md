赛事页面最显眼的是比分，但最容易引起误解的往往是状态：一场比赛没有开赛，显示 0:0；一个接口半小时没更新，页面还写“实时”；延期的比赛沿用原来的开始时间。本文把这些问题拆成数据字段与展示规则，作为数据产品设计练习。

## 先区分未知与真实的零

下面这条记录完全是教学样例，不对应真实球队或赛事：

```json
{
  "id": "demo-match-001",
  "homeTeam": "示例甲队",
  "awayTeam": "示例乙队",
  "scheduledAt": "2026-06-14T18:00:00Z",
  "status": "scheduled",
  "score": null,
  "sourceUpdatedAt": "2026-06-14T17:40:00Z",
  "fetchedAt": "2026-06-14T17:40:10Z"
}
```

未开赛时 `score` 是 null，意味着还没有比赛得分。只有在确认比赛已经进行、数据源明确报告零进球时，0:0 才是一个结果。页面遇到 null 应显示“尚未开赛”或“比分待更新”，而不是用两个零补空值。

同理，接口错误不能转换成 0:0。否则一次网络故障就会伪造比赛状态。结构上允许未知，显示上才能诚实地表达未知。

## 保存一个时间，显示时明确时区

样例中的开始时间带 `Z`，表示 UTC。若页面面向北京时间，可以显式指定 `Asia/Shanghai`，而不是直接截取字符串前十位作为比赛日期。

```js
const kickoff = new Date('2026-06-14T18:00:00Z');
const formatter = new Intl.DateTimeFormat('zh-CN', {
  timeZone: 'Asia/Shanghai',
  month: '2-digit', day: '2-digit',
  hour: '2-digit', minute: '2-digit', hour12: false,
});
console.log(formatter.format(kickoff));
// 北京时间为 6 月 15 日 02:00；具体分隔符取决于运行环境。
```

“今日赛程”的分组也必须按同一个时区计算。否则列表归在 6 月 14 日，卡片却写 6 月 15 日凌晨，用户会误以为两场比赛。可提供本地时间选择，但切换后日期分组和卡片时间要同步变化。

## 比赛状态应由数据源明确给出

不能因为当前时间晚于预计开赛时间，就在前端自动标成“进行中”。比赛可能延期，也可能因为数据源故障没有新状态。

| 数据状态 | 页面文案 | 比分策略 |
| --- | --- | --- |
| scheduled | 未开赛 | 显示时间，不补零 |
| live | 进行中 | 展示有效比分与更新时间 |
| finished | 已结束 | 展示最终比分 |
| postponed | 已延期 | 单独显示重新安排信息 |
| cancelled | 已取消 | 不制造赛果 |
| unknown | 状态待确认 | 显示来源异常提示 |

这只是示例枚举，真实 API 可能还有中场、加时、点球等状态。接入时需要写明映射，而不是把无法识别的状态默认当作已结束。点球比分也不宜与常规比分混在一个字符串里，应根据产品需求单独建模并标注。

## 刷新时间不等于数据新鲜

`fetchedAt` 表示本系统最近取得响应的时间，`sourceUpdatedAt` 表示来源报告数据更新时间。接口每分钟都返回同一份过期数据时，前者一直变化，后者不变。只展示“刚刚刷新”会让用户高估实时性。

页面可以把两者分别写为“页面获取时间”和“来源更新时间”。如果来源根本没有更新时间，就明确说明缺少该信息。不要把获取时间填入来源更新时间字段以消除空值。

对过期阈值也需要上下文。正在进行的比赛和几天后的赛程，对刷新速度的要求不同。本文没有实际数据供应商或延迟测量，因此不指定一个看似精确的通用阈值；产品应根据来源协议和观测结果决定。

## 怎样验证这个设计

在接入真实数据前，可以先用固定样例测试四个场景：跨午夜的比赛、延期比赛、null 比分、来源时间停止更新。每个场景都有明确预期，前端不必等真实赛事发生才知道页面如何表现。

进一步的异常检查包括：同一比赛 ID 重复、队名缺失、时间格式非法、时钟比服务器快。排序时给无法解析的时间单独位置并显示提示，比静默扔掉整场比赛更便于排错。

World Cup Live 为这篇笔记提供了问题背景，本文不提供赛事直播或视频流。模型是否适合某个真实项目，仍需结合数据授权、字段协议和延迟验证。日期格式化可参考 [MDN Intl.DateTimeFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat)。
