下载页写一个“立即下载”，对读者来说信息不够。设备能不能安装、是否会覆盖已有应用、下载是否完整、这个版本是不是正式版，是不同的问题。本站的听伴和 RouteDeck 下载页把这些信息分开列出，本文解释怎样使用它们。

## 先看版本边界，再下载文件

下面是本次检查 `src/config/apps.json` 得到的目录快照。它描述网站当前提供的版本，不代表所有设备上的最新版本。

| 字段 | 听伴 | RouteDeck |
| --- | --- | --- |
| 版本名 | 0.5.6 | 0.2.3-preview |
| versionCode | 23 | 5 |
| 包名 | com.imspring.tingban | com.imspring.routedeck |
| 架构说明 | 通用 APK | 仅 arm64-v8a |
| 最低系统说明 | Android 10 | Android 10 |
| 发布边界 | Debug 签名内部测试 | 内部测试预览 |

这里最容易误读的是“通用”和“预览”。通用 APK 不等于任何设备都兼容，系统版本和硬件能力仍然有限制；预览也不等于已经适合长期生产使用。先阅读[听伴页面](/apps/tingban/)或[RouteDeck 页面](/apps/routedeck/)的功能边界和隐私说明，再决定是否下载。

## SHA-256 回答的是文件是否一致

本站的下载地址和校验值由同一份配置渲染，二维码则由 `npm run generate:qrs` 读取这份配置预先生成。更新下载地址时，也要重新生成二维码并核对扫码结果，不能只改按钮链接。二维码是本地生成的静态 SVG，扫码不会先把地址交给第三方二维码生成服务。

在 macOS 下载完成后，可在终端执行：

```sh
shasum -a 256 ~/Downloads/tingban-0.5.6-v23-com.imspring.tingban-universal-debug.apk
```

Windows PowerShell 的对应检查是：

```powershell
Get-FileHash -Algorithm SHA256 "$env:USERPROFILE\Downloads\tingban-0.5.6-v23-com.imspring.tingban-universal-debug.apk"
```

把输出的 64 位十六进制值与下载页的 SHA-256 逐字比较。本站目录中听伴这个版本的值是：

```text
1af9759ea38a4a8ad9043fac4190e86ec6c93d46481c27f5f6e3ec992df56640
```

如果不一致，先不要安装：检查是否下载了同名旧文件、浏览器是否添加了数字后缀、下载是否中断、页面对应的版本是否一致。重新下载后再次比较，仍不一致就把版本和不匹配现象反馈给作者。

一致只说明文件与网站公布的那份相同，不能证明文件没有恶意行为。如果下载页和文件同时被替换，单独对照同站公布的哈希也不能提供独立信任。来源可信度、签名验证、权限评估仍然重要。

## 包名与签名决定升级能否连续

版本名是给人看的，versionCode 是 Android 使用的版本序号。包名不同通常会被识别成不同应用，文件名相同并不能改变这一点。对于同一应用的常规覆盖升级，签名身份也需要匹配。

有 Android SDK Build Tools 时，可以用官方工具检查下载文件，下面的 `your-app.apk` 需要替换成实际文件路径：

```sh
apksigner verify --verbose --print-certs your-app.apk
```

这一步验证 APK 签名并显示证书信息，不会安装应用。不要把它显示“验证成功”理解成“官方审核安全”：它验证的是签名结构和文件完整性。若要判断能否覆盖已有版本，还需与可信旧版本的证书及安装环境比较。

尤其是内部测试包，不要为了绕过签名不匹配就先卸载旧应用。卸载可能清除应用数据。正确顺序是确认应用身份、导出或备份重要数据、核实升级方案，再决定安装方式。本站网页无法替你读取设备里的旧版本状态。

## 下载页怎样避免让人点错

本站的 APK URL 使用版本化文件名。这样文章和截图讨论的文件有明确对象，不会因为一个 `latest.apk` 被覆盖而失去可追溯性。但固定链接也意味着可能不是项目的最新开发构建，页面应明确写出版本。

界面上，下载按钮、隐私说明、校验值应放在一起，广告不应该伪装成下载入口。对于大文件，显示文件大小和架构比额外增加一个吸引点击的按钮更有帮助。本站听伴目录标注约 384.2 MB，因此移动网络用户应先确认流量和剩余空间。

## 出现问题时提供什么信息

通过[联系页](/contact/)反馈时，提供应用版本、设备型号、Android 版本、错误文本，以及哈希是否一致即可。不要上传录音、聊天内容、服务 token 或完整设备备份。应用崩溃和下载损坏是不同的问题：前者需要复现步骤，后者先从文件完整性开始。
